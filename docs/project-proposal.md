# 项目提案 (Project Proposal)

## 项目名称
健身房会员管理系统

## 目标用户
- **管理员**：负责会员卡种管理、教练排班和系统设置。
- **教练**：查看排课、确认学员签到。
- **会员**：购买会员卡/课包、在线预约课程、到店签到。

## 优先实现业务场景
**会员课程预约与签到**：会员登录后，查看可预约课程并完成预约。到店后通过系统签到，系统自动扣减课时，教练确认核销。这是健身房最核心、最高频的业务环节。

## 核心模型 (Domain Models)
1. **会员 (Member)**：存储会员基本信息、会员卡状态、剩余课时等。
2. **课程 (Course)**：存储课程名称、教练、上课时间、容量限制等。

## 本周（作业04）更新：业务建模完善

**1. 核心业务流程：**
会员发起预约 -> 系统校验会员剩余课时是否充足 -> 系统校验课程名额是否已满 -> 校验通过则扣减会员课时、增加课程已预约人数 -> 返回预约成功。

**2. 参与业务实体及关系：**
- Member（会员实体）：包含姓名、电话、剩余课时等。
- Course（课程实体）：包含课程名、教练、容量、已预约人数等。
- 关系：会员与课程为多对多关联，当前单体阶段通过 Service 层的逻辑进行关联和一致性维护。

**3. Service 检查的业务规则：**
在 `BookingService` 中，强制校验两条规则：① 会员的 `remainingSessions` 必须大于 0；② 课程的 `bookedCount` 必须小于 `capacity`。否则抛出异常并阻断。
